# Handy custom words research

Checked 2026-09-16 against official `cjpais/Handy` source at `ba10ce1943ef34e93c09494027fc0b9ced2e8a44`. Firecrawl had zero credits; research used official web documentation and a checkout of the official repository.

## Behavior

Handy's Advanced settings let users save frequently misheard names and terms. The documentation describes automatic correction of similar-sounding words and explicitly calls the feature imperfect. Examples include `astro js` becoming `Astro.js`. [Official documentation](https://handy.computer/docs/advanced#custom-words)

Current Handy passes saved words, joined by commas, as a Whisper initial decode prompt and skips fuzzy correction for that path. Other models, including Parakeet, use fuzzy text correction after transcription. Streaming finalization also uses text correction. The relevant Parakeet feature does not retrain the model or bias its acoustic decoder. [Model dispatch](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/managers/transcription.rs#L1299), [postprocessing selection](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/managers/transcription.rs#L1491), [stream finalization](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/managers/transcription.rs#L1136)

## Matcher

- Comparison keys remove punctuation and spaces and lowercase letters and digits. An ampersand also gets a key with `and` expanded. The current fallback deliberately rejects non-ASCII keys because its tokenization and Soundex scoring are unsuitable for CJK. Numeric keys receive no phonetic bonus. [Key construction](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/audio_toolkit/text.rs#L8)
- Each transcript position considers spans of one to three whitespace-separated words. It avoids crossing trailing punctuation on interior words, ignores candidates over 50 normalized characters, and rejects length differences over `max(25% of the longer length, 2)`. [Matcher](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/audio_toolkit/text.rs#L79)
- Score is Levenshtein distance divided by the longer key length. A matching Soundex code multiplies it by 0.3. Lower is better; acceptance requires strictly less than the configured threshold, default 0.18. Across span lengths, lowest score wins; ties retain the earlier, longer span. Zero actually disables even exact matches because the comparison is strict, despite the code comment describing zero as exact-only. [Scoring and selection](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/audio_toolkit/text.rs#L110), [default](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/settings.rs#L596)
- Entries may contain spaces. A test covers `Mac Book Pro` becoming `MacBook Pro`, but the spoken input span still cannot exceed three tokens. Leading and trailing punctuation survive. Saved spelling normally survives; an uppercase source forces uppercase, and an initial source capital capitalizes the replacement's first character. [Replacement and casing](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/audio_toolkit/text.rs#L204), [phrase test](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src-tauri/src/audio_toolkit/text.rs#L766)

## UI

The UI offers a text field, Add button, Enter-to-add, and removable chips. It collapses whitespace, trims, strips angle brackets and quote characters, rejects empty entries and entries over 50 characters, and checks duplicates case-sensitively. Debug settings separately expose the correction threshold from zero to one. These are implementation choices, not requirements to copy. [CustomWords component](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src/components/settings/CustomWords.tsx), [threshold control](https://github.com/cjpais/Handy/blob/ba10ce1943ef34e93c09494027fc0b9ced2e8a44/src/components/settings/debug/WordCorrectionThreshold.tsx)

## Outspoke recommendation

Implement custom vocabulary as a local, deterministic text transform. Say it corrects similar recognized words. It cannot recover speech the decoder omitted entirely. This matches Handy's Parakeet behavior without network access or a change to `SpeechEngine`.

Store preferred terms in `AppPreferences`, expose add/remove through `PreferencesViewModel`, and add Custom words to the existing settings screen. Check duplicates case-insensitively but retain preferred spelling. An empty vocabulary should be a no-op. Snapshot vocabulary at recording start so settings changes cannot alter committed text midway through dictation.

Keep matching in a pure, bounded `CustomWordCorrector` and compile term keys once per vocabulary. Support exact normalized multiword matches and conservative fuzzy matches. Handy's broad Soundex bonus can replace ordinary words incorrectly. Reject ambiguous ties, protect short words and number sequences, and preserve punctuation boundaries. Reuse existing edit-distance or phonetic helpers where their behavior fits. Do not silently exclude accented names merely because Handy's Soundex fallback does.

Streaming integration needs care. `InferenceRepository.cleanTranscript` warns that word-count changes must stay separate from raw alignment anchors. `TextInjector` re-cleans frozen and composing slices through `displayCleanFn`. Correcting only finals conflicts with committed partials; independently correcting slices can split a phrase at the freeze boundary. Integrate the same session vocabulary into the established display transform path and retain enough mutable raw words for the longest phrase. Verify partials, finals and window trims through `TextInjector`, and avoid double correction. [Repository cleaner](../app/src/main/kotlin/outspoke/inference/InferenceRepository.kt), [editor integration](../app/src/main/kotlin/outspoke/ime/TextInjector.kt), [IME display cleaner](../app/src/main/kotlin/outspoke/ime/OutspokeInputMethodService.kt)

Tests should cover brand casing, multiword misrecognitions, punctuation, ordinary-word false positives, ambiguity, numbers, non-ASCII terms, empty vocabulary, and phrases spanning partial/freeze/trim boundaries. Replay the user's recording with an unrelated vocabulary to check that custom words neither lose nor invent numbered sentences.
